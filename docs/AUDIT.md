# Разбор клиента Angel Visuals 0.5.14

Дата: 2026-11-06. Исходников в этом репозитории нет (только `README.md`, а jar,
манифест и установщик лежат в GitHub Releases), поэтому разбор сделан по
опубликованному `angel-visuals-0.5.14.jar` и `manifest.json`: структура jar,
байткод через `javap`, ресурсы, языковые файлы. Сам код клиента отсюда
поменять нельзя — правки ниже нужно вносить в исходный репозиторий.

## Общая картина

| Что | Значение |
|---|---|
| Размер jar | 18,6 МБ (770 файлов) |
| Из них классы | 2,5 МБ, 582 класса |
| Из них картинки фонов | **16,0 МБ (86 % jar)** — 7 PNG 1920×~850 |
| Миксины | 64 |
| Модулей в меню | 63 |
| Ключей локализации | 1072 (ru и en совпадают 1:1) |

Код в целом аккуратный: есть кэш строк для HUD (`TextCache`), фоны грузятся
лениво и освобождаются, проверка Iris через рефлексию кэшируется по времени,
токены Microsoft шифруются через Windows DPAPI, манифест обновлений подписан.
Ниже — то, что реально стоит исправить.

## 1. Что работает криво

### 1.1. Фоны раздувают jar в 7 раз
Семь фонов — 16 МБ из 18,6. Каждое обновление клиента заставляет всех
игроков заново качать ~16 МБ одинаковых картинок.

**Решение:** `tools/optimize_textures.py` (добавлен в этот репозиторий).
Проверено на ресурсах 0.5.14:

| Режим | Картинки | jar примерно |
|---|---|---|
| сейчас | 16,4 МБ | 18,6 МБ |
| без потерь (по умолчанию) | 11,5 МБ | ~13,7 МБ |
| `--lossy` (палитра 256 + дизеринг только для фонов) | **6,4 МБ** | **~8,7 МБ** |

В режиме `--lossy` все текстуры, кроме фонов, остаются пиксель-в-пиксель
такими же (проверено), фоны — PSNR 42–46 дБ, на глаз отличий нет даже при
2× увеличении. Minecraft читает индексированные PNG штатно, но после сборки
один раз открой все экраны в игре.

```bash
python3 tools/optimize_textures.py src/main/resources/assets --dry-run
```

```bash
python3 tools/optimize_textures.py src/main/resources/assets --lossy
```

Ещё лучше — вообще не класть фоны в jar, а качать их лаунчером отдельным
файлом из манифеста (меняются редко, обновления клиента станут ~2–3 МБ).

### 1.2. Первое открытие экрана с фоном подвисает
`BackdropTextures.load` декодирует PNG 1920×850 (до 3 МБ) прямо в потоке
отрисовки при первом показе экрана — это заметный фриз на слабых ПК
(главное меню, пауза, загрузка мира). Варианты: декодировать `NativeImage`
в фоновом потоке (`CompletableFuture.supplyAsync`) и загружать в GPU уже
готовую картинку на следующем кадре, пока показывать сплошной цвет
(у тебя уже есть `cellColors` — средние цвета клеток, их и рисовать как
заглушку). После сжатия из п. 1.1 декодирование тоже станет быстрее.

### 1.3. «Динамическая дальность прорисовки» вызывает фризы
`PerformanceModule.adapt` раз в ≥15 с меняет эффективную дальность
прорисовки на ±2 чанка через `OptionsRenderDistanceMixin`. В Minecraft
(и в Sodium) смена дальности = полная перестройка всех чанков, это
секундный лаг именно в момент, когда FPS и так просел. Получается
«лечим просадку FPS ещё большей просадкой». Настройка выключена по
умолчанию — **предлагаю удалить её** вместе с `minDistance` и миксином.
Отсечение сущностей/частиц и снижение качества эффектов в модуле полезны,
их оставить.

### 1.4. Описание «Игрового меню» не соответствует меню
В `ru_ru.json`, `en_us.json` и в манифесте сказано, что в меню есть
«Options, Generate new level, Save level, Load level и Back to game».
Таких пунктов нет (это меню Minecraft Classic 2009 года). В
`PauseMenuScreen$Item` реально: Вернуться в игру, Достижения, Статистика,
Отзыв, Сообщить об ошибке, Настройки, Открыть для сети / Жалобы,
Выйти в меню. Поправить текст `skolopendra.module.pause_menu.description`.

### 1.5. Лаунчер не подписан
Каждый новый пользователь видит предупреждение SmartScreen. Для бесплатного
проекта терпимо, для платного — нет: люди не будут платить за то, что
Windows называет опасным. См. `docs/LEGAL.md`, раздел про подпись кода.

### 1.6. 20 миграций конфигов
`config/migration` — 20 классов миграций со времён 0.3–0.5. Пока
пользователей мало, их можно «сплющить»: зафиксировать минимальную
поддерживаемую версию конфига (например 0.5.0), всё старее — сбрасывать
на значения по умолчанию с уведомлением. Меньше кода, который запускается
при каждом старте и который надо поддерживать.

## 2. Почти бесполезные / лишние функции

Мнение по описаниям модулей; решать тебе.

| Модуль | Почему | Что сделать |
|---|---|---|
| Перемещение HUD в чате | Это не функция, а способ настройки HUD; отдельный переключатель только путает | Сделать всегда включённым, убрать из списка |
| Цели | Настройка, а не функция (дальность 3,5 блока и т. п.) | Перенести в настройки Target HUD / маркеров |
| Свой ник | Ник над собой в F5 — мелочь | Сделать опцией в «Камере» или «Друзьях» |
| Главное меню + Игровое меню | Два модуля одного стиля | Объединить в «Меню клиента» с двумя галками |
| 11 маркеров цели, у sko1opendra 2 вида | Перегруз выбора; `CentipedeMarker` — самый большой класс среди визуалов (31 КБ) | Один модуль «Маркер цели» с выпадающим выбором стиля |
| Производительность → динамическая дальность | См. 1.3 | Удалить |

## 3. Функции, из-за которых будут проблемы на серверах

Эти модули дают **игровое преимущество**, а не просто меняют картинку. На
многих серверах (особенно PvP) их запрещают правила или режут античиты:

- **Fast EXP** — уменьшает задержку использования предмета
  (`MinecraftUseDelayAccessor`): по умолчанию 1 тик вместо ванильных 4
  (настройка 1–3). Классический флаг античита.
- **Item Scroller** — серия кликов по слотам; задержка по умолчанию 50 мс,
  но её можно поставить **0 мс** — это пачка кликов за один кадр, античиты
  ловят как «быстрые клики в инвентаре».
- **Хитбоксы, Траектории, Подсветка руд, Полная яркость, Числа урона,
  Таймер TNT, Свободный обзор** — разрешены не везде.

Пока клиент бесплатный, это проблема игроков. Если клиент платный —
покупатель получает бан из-за твоего продукта и идёт требовать деньги
назад. Рекомендации:

1. Вынести эти модули в отдельную категорию «Утилиты» с пометкой
   «может быть запрещено на сервере».
2. Добавить **серверный блок-лист** (см. п. 4.2).
3. У Fast EXP поставить по умолчанию 3 тика, у Item Scroller минимум
   задержки поднять с 0 до 30–50 мс.

## 4. Что добавить для оптимизации

### 4.1. Сделано: `tools/optimize_textures.py`
Сжатие PNG без потерь + палитра для больших фонов. Встраивается в сборку:

```groovy
// build.gradle
def optimizeTextures = tasks.register('optimizeTextures', Exec) {
    dependsOn tasks.named('processResources')
    commandLine 'python3', 'tools/optimize_textures.py',
                layout.buildDirectory.dir('resources/main/assets').get().asFile.path,
                '--lossy'
}
tasks.named('jar') { dependsOn optimizeTextures }
```

(Так сжимаются копии в `build/`, исходники в `src/` не трогаются.)

### 4.2. Предложение: блок-лист функций по серверу в манифесте
Манифест уже подписан и скачивается лаунчером. Добавить в него раздел:

```json
"serverRules": [
  { "match": "*.example-pvp.net", "disable": ["fast_exp", "item_scroller", "hitboxes"] }
]
```

Клиент при подключении сверяет адрес и выключает перечисленные модули до
выхода с сервера. Это и защита игроков от банов, и аргумент для владельцев
серверов «разрешите Angel Visuals». Обновляется без выпуска нового jar.

### 4.3. Предложение: фоны отдельно от jar
См. конец п. 1.1. Экономит трафик при каждом обновлении.

### 4.4. Предложение: «лёгкий режим» одним переключателем
Для слабых ПК: выключает тяжёлые вещи (лучи света, густой туман, свечение
рук, объёмные крылья, трейлы, маркер sko1opendra Real), ставит частицы на
минимум. Пресет поверх существующих настроек, нового кода рендера не нужно.
